Chapter 14. Evidence for your report

The tables below list every screenshot and text output your thesis uses, with the thesis chapter it goes in and a caption you can adapt. The second half of the chapter is one capture session that recreates the flat network, the baseline-only state and the segmented network in order, so you can collect everything in one afternoon even if you saved nothing earlier. At the end, a single command checks that all 33 evidence IDs have their files. Read the capture rules before chapter 8, so the outputs you see during the attack already look right, and run the full capture session on day 6 as chapter 15 plans it. The session takes about two and a half hours, plus up to an hour for the connectivity test.

Where each piece goes: thesis chapters 2 to 5

The thesis chapter column uses chapter 2 for background, chapter 3 for design, chapter 4 for implementation, chapter 5 for results, and the appendix. If your template numbers them differently, keep the mapping and change the numbers.

An evidence file is a screenshot or a saved text output that proves one claim in your thesis. A caption is the sentence printed under a figure or a table in the thesis, telling the reader what it shows. Every evidence file in this chapter has an ID such as E14. The IDs exist only so you can find your files. Your thesis gives each figure its own number, such as Figure 5.3, and the caption goes under it. As you place each evidence file in your thesis, write its ID next to the figure number it gets, in a small list such as E21 = Figure 5.3.

Capture rules

Follow these for every capture.

  1. The date and time must appear inside the same screenshot as the output. In the Ubuntu terminal the capture command prints date before and after the output, so when an output runs past one screen, you capture its last screen and the closing date is still in it. In PowerShell each capture block starts with Get-Date. Browser screenshots use full-screen mode, which puts the clock in the Windows taskbar into the picture.
  2. Use a light terminal theme with 14 pt text. The next step sets this up once.
  3. Crop, never edit. You may cut away empty space around the window. You may not paint over, highlight, retype or move anything. If a capture has a mistake, capture it again.
  4. Keep the .txt next to every terminal and PowerShell .png, under the same name. E10-portal-flat.png sits next to E10-portal-flat.txt. The text file lets you quote exact lines in the thesis and proves the picture wasn't altered. For rows marked browser and terminal, the .png is the browser screenshot, so don't take a terminal screenshot for those.
  5. Name every file E<two-digit number>-<short name>, with no spaces, for example E03-nodes.png. The checkpoint at the end counts files by their number.
  6. Never mix states in one screenshot. In dashboard screenshots, keep the "Policies:" line at the top of the page in view, so the picture shows which state the lab was in. If the part you need and the Policies line don't fit on one screen, zoom the browser out with Ctrl and the minus key until they do. Zooming isn't editing.

Set up a terminal look for screenshots

A light theme and larger text make every later screenshot readable on paper. Windows Terminal is the window that hosts both your Ubuntu and your PowerShell tabs on Windows 11, and it stores a separate look for each.

  1. Open Windows Terminal and press Ctrl+, (Ctrl and the comma key) to open its settings.
  2. In the left-hand list under "Profiles", click your Ubuntu profile. Its name contains Ubuntu and 24.04.
  3. Under "Additional settings", click "Appearance".
  4. Set "Color scheme" to "One Half Light" and "Font size" to 14.
  5. Click "Save".
  6. Repeat steps 2 to 5 for the "Windows PowerShell" profile.

If you work in the terminal inside VS Code instead, open File > Preferences > Settings, search for terminal.integrated.fontSize and set it to 14, then pick a light theme with File > Preferences > Theme > Color Theme. Use one of the two windows for all your captures, so the screenshots look alike.

You should see dark text on a white or light grey background in both profiles, larger than before.

If you see this instead

The settings page has no "Appearance" entry under your profile. You're in an older Windows Terminal. Open the Microsoft Store, search for Windows Terminal and click "Update", then try again.

The colours changed in the Ubuntu tab but not in PowerShell. Each profile has its own appearance. Repeat the steps for the Windows PowerShell profile.

Make the two evidence folders (Ubuntu and Windows)

Text outputs from Ubuntu go straight into ~/microseg/evidence. Screenshots and PowerShell outputs are made on the Windows side, so they need a Windows folder first, and you copy them across at the end of the session. Make the Ubuntu folder first.

ls -d prints a folder's own name instead of listing what is inside it, and it fails when the folder doesn't exist. The first ls -d checks that you're in the Ubuntu that holds your project, since ~/microseg/k8s has been there since chapter 6. && runs the next command only if the one before it worked. mkdir -p creates the evidence folder, and does nothing if it already exists. The last ls -d prints the new folder.

You should see two lines, the full path of the k8s folder and then that of the evidence folder.

Both paths start with /home/, followed by your own Linux user name and /microseg.

Now open PowerShell and make the Windows folder.

New-Item -ItemType Directory creates a folder. -Force stops it from failing when the folder is already there. $HOME is your Windows user folder, C:\Users\<WinUser>, so the new folder is C:\Users\<WinUser>\microseg-evidence. It sits outside Documents on purpose, because on many laptops OneDrive moves Documents somewhere else.

You should see a short table describing the new folder.

The column that matters is Name, which must read microseg-evidence. Your date and time will differ.

If you see this instead

This Ubuntu has no project in it, so you're in the wrong Linux user or the wrong Ubuntu. Close the tab, open the Ubuntu-24.04 profile from chapter 2, not another distribution, and run the command there.

You're in Command Prompt, not PowerShell. Close it, open Windows PowerShell and run the command there.

Capture a terminal output

Every Ubuntu capture uses the same wrapper around the command you want to record. The example below captures E03, the node list. E03 is the one capture you can make the first time you read this chapter, because the node list looks the same in every state of the lab.

clear empties the terminal so the screenshot holds only this capture. The braces { ... } make a brace group, which runs several commands as one so their output travels on together. Inside it, date prints the date and time, kubectl get nodes -L tier prints the nodes, and the second date prints the time again once the command has finished. Each command inside the braces ends with ;, and the space after { is required. 2>&1 adds standard error to the output. Standard error is the second output channel a program uses for error messages, and without this part, errors would show on screen but be missing from the file. The | passes everything to tee, a program that prints what it receives and writes the same text into a file, so you see the output and save it in one go.

You should see the date, then the three nodes, then the date again.

Your dates and the AGE column differ. All three nodes must say Ready and the TIER column must read frontend for kind-worker and backend for kind-worker2.

Now take the screenshot. Press Windows+Shift+S. A small toolbar appears at the top of the screen with the rectangle mode already selected, so drag a rectangle around the terminal window. A notification appears in the corner of the screen. Click it to open the picture in the Snipping Tool, the screenshot program built into Windows, and press Ctrl+S. In the "Save As" window, click the address bar at the top, type %USERPROFILE%\microseg-evidence and press Enter. Type E03-nodes as the file name, keep the type as PNG and click "Save".

If you see this instead

The evidence folder doesn't exist yet. Run the mkdir step above, then the capture again.

The cluster isn't running, usually after Windows restarted. Chapter 13 explains how to bring the lab back after a Windows reboot. Do that, then capture again.

There's no space after the opening brace. If the prompt changes to > and waits instead, the ; before the closing brace is missing. Press Ctrl+C and copy the command again.

No notification appears after you drag the rectangle. Notifications are switched off, or Do Not Disturb is on. The Snipping Tool still saves a copy of every screenshot. Open File Explorer, go to Pictures > Screenshots, rename the newest file to E03-nodes.png and move it into C:\Users\<WinUser>\microseg-evidence.

Capture a PowerShell output

The attack steps are sent from Windows, so their evidence comes from PowerShell. Read this section now, but don't run these blocks yet. You run them in part 2 of the capture session as E13 and in part 4 as E22. Run now, they would attack the lab in whatever state it's in and change Omar's grade.

PowerShell's own way of saving output writes a text format that looks broken in Ubuntu, so these captures let curl.exe save the answer itself with -o and then show the saved file with Get-Content. A variable called $id holds the evidence ID, which lets you run the same five blocks twice, once on the flat network as E13 and once on the segmented network as E22. Paste one block at a time and take a screenshot after each one, saving it as E13-step1, E13-step2 and so on.

cd moves PowerShell into the Windows evidence folder, so files are saved there. $id = "E13" stores the text E13 in a variable, and PowerShell puts it wherever $id appears later, so "$id-step1.txt" becomes E13-step1.txt. Clear-Host empties the window and Get-Date prints the date. The curl.exe line is attack step 1 from chapter 8 with -o "$id-step1.txt" added, which writes the answer into the file instead of the screen. Get-Content then prints the file.

Part 5, the toggle test

The toggle test shows that only the policies change the result. It removes the policies, runs the attack and the matrix, puts the policies back and runs both again, all inside one capture.

This is the same wrapper spread over several lines, and bash waits for the closing brace before it runs anything. While it pastes, each new line starts with >, which is bash waiting for that brace, so you have nothing to type. kubectl delete -f and kubectl apply -f with the folder name remove or create the policies of both files. The jq programs turn the dashboard's answers into one short line each. In the attack line, select(.success) keeps the steps that succeeded, length counts them, and \(.) puts the count into the sentence. In the matrix line, \(.open) and \(.total) take the two counts from the answer. The block takes about a minute.
